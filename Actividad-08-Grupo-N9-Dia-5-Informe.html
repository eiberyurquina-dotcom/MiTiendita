01 · El proyecto

Una herramienta práctica para el comercio cotidiano.

La aplicación está diseñada para que la persona que atiende la tienda encuentre productos rápido, arme una compra con varios artículos y mantenga a la vista existencias, ventas y productos por vencer.

Propósito

Digitalizar tareas que suelen llevarse en papel o de memoria: registrar productos, actualizar cantidades, consultar precios y guardar cada venta. La cámara añade una forma visual de encontrar artículos sin depender de escribir su nombre.

Mi tiendita está enfocada en una tienda de barrio: no usa códigos de barras como flujo principal ni requiere un sistema de caja de supermercado.

Propuesta de valor
“Enfocar, reconocer, agregar a la compra y continuar atendiendo.”
Un flujo corto, desde el producto hasta el registro de la venta.

02 · Funciones principales

Lo esencial, en un solo lugar.

Tres áreas conectadas organizan el trabajo: inventario para preparar el catálogo, venta para atender al cliente y Control para revisar el movimiento del negocio.

01

Inventario directo

Registra nombre, precio, existencias, foto y fecha de vencimiento opcional. Busca por nombre y agrega unidades a un producto ya creado.

02

Venta con varios artículos

Selecciona cantidades, suma productos al carrito y consulta el detalle y el total desde un acceso fijo en la pantalla de venta.

03

Reconocimiento con cámara

La cámara enfoca el envase y consulta la IA. Al reconocerlo, muestra su precio y disponibilidad para elegir cuántas unidades vender.

04

Alertas de vencimiento

La fecha se selecciona con un calendario. En Android o iOS se puede programar una notificación local tres días antes.

05

Dos formas de pago

Registra ventas en efectivo o muestra el QR de la tienda y captura una foto del comprobante para registrar el pago QR.

06

Control con acceso

Una sección protegida reúne resúmenes de ventas, productos más vendidos, comprobantes QR y administración de la cuenta.

03 · Flujo de venta

Del primer producto al cierre de compra.

La venta se construye en el teléfono: cada artículo y cantidad se agrega al detalle, se confirma el total y se registra el método de pago elegido.

Encontrar

Busca el artículo por nombre o abre el escáner y presenta un solo producto a la cámara.

Elegir cantidad

Define cuántas unidades quiere el cliente. La aplicación comprueba que haya existencias suficientes.

Revisar el detalle

Consulta artículos, cantidades, subtotales y total desde el panel accesible en la misma pantalla.

Confirmar y descontar

El registro de la venta y la actualización del inventario se realizan juntos en la base de datos local.

04 · Reconocimiento visual

Una IA que se puede ampliar con nuevos productos.

El teléfono toma imágenes temporales de la cámara y las envía al servicio de reconocimiento de la computadora. Para evitar mostrar una lectura inestable, la aplicación exige confianza mínima de 0,70 y dos predicciones consecutivas de la misma clase.

Para registrar una clase nueva, el flujo solicita cinco fotos. La API incorpora las imágenes al conjunto de entrenamiento, actualiza el modelo y devuelve el catálogo de clases. Las clases existentes también pueden reentrenarse con las imágenes guardadas en el dataset.

05 · Control de la tienda

Una vista privada para entender las ventas.

La persona responsable puede revisar periodos y administrar la configuración necesaria para los cobros QR, sin mezclar ese panel con la atención de cada venta.

Resumen interactivo

Semana, mes y año

Al elegir un periodo, Control calcula ingresos registrados, número de compras y unidades vendidas.

  • Gráfico seleccionable con los diez productos más vendidos.
  • Detalle de unidades e ingresos por producto seleccionado.
  • Los datos provienen de ventas guardadas localmente en el teléfono.
Acceso del propietario

Cuenta editable

Existe una cuenta inicial para entrar al panel. Después se puede cambiar el usuario y la contraseña; se solicita la contraseña vigente para aplicar el cambio.

  • La app guarda las credenciales locales como hash con sal.
  • Conviene sustituir la cuenta inicial antes de entregar el teléfono.
Configuración de cobro

QR propio de la tienda

El propietario carga desde la galería el QR de la cuenta donde recibe pagos; la pantalla de venta lo presenta al cliente.

Registro y evidencia

Comprobantes QR

Después de tomar la foto del comprobante, la app registra la venta y actualiza inventario. Control muestra los últimos 50 pagos QR con su detalle y la imagen guardada.

!

Alcance del pago QR: la aplicación conserva la foto como respaldo y registra la operación; no se conecta al banco ni verifica automáticamente que la transferencia haya sido acreditada. El encargado debe comprobar el pago antes de fotografiar el comprobante.

06 · Tecnología y funcionamiento

Móvil en la tienda; reconocimiento en la red local.

La arquitectura separa la experiencia de venta del procesamiento del modelo. Los registros comerciales viven en el dispositivo y la API de IA se ejecuta en una computadora accesible desde la misma red.

01 · Aplicación

Expo + React Native

Interfaz móvil con cámara, selector de fotos, notificaciones locales y navegación entre Inventario, Registrar venta y Control.

02 · Datos del negocio

SQLite en el teléfono

Productos, ventas, líneas de compra y configuración se guardan en la base de datos local del dispositivo.

03 · IA local

Python + TensorFlow

La API local ofrece reconocimiento, entrenamiento de nuevas clases y reentrenamiento del catálogo del modelo.

i

Requisito de uso del escáner: la computadora que ejecuta la API y el teléfono deben estar conectados a la misma Wi-Fi. El escáner no funcionará si la URL local no está configurada o si el servicio no está activo. Los datos de inventario y ventas no se sincronizan automáticamente entre teléfonos.

Instalación y puesta en marcha

Con Android Debug Bridge (ADB) y un teléfono conectado por USB con depuración activada:

adb install -r "C:\Users\Rey Paimon\Documents\Aplicacion Movil\Proyecto-Final\android\app\build\outputs\apk\release\app-release.apk"

Para iniciar la app de desarrollo con la IA local, usar npm start en el proyecto. El primer inicio requiere configurar la API con API_TIENDA\setup_api.bat; el launcher inicia la API y espera a que responda antes de abrir Expo.

!

Antes de publicar: esta APK está firmada con una clave de depuración para pruebas; no es una firma de distribución de Play Store. Se recomienda configurar una clave de firma de producción, rotar la cuenta inicial de Control y probar permisos, notificaciones y cámara en el teléfono objetivo.

08 · Evolución recomendada

Una base lista para seguir creciendo.

La siguiente etapa puede enfocarse en proteger la operación, mejorar la continuidad de los datos y ampliar el reconocimiento con imágenes variadas de los productos reales de cada tienda.

Prioridad 01

Preparar distribución

Crear firma de producción, respaldar los registros y definir cómo restaurarlos al cambiar de teléfono.

Prioridad 02

Fortalecer la conexión

Proteger la API local con autenticación y transporte seguro si el uso deja de limitarse a una red de confianza.

Prioridad 03

Mejorar el modelo

Agregar fotos con distintos fondos, ángulos e iluminación y comprobar el reconocimiento en condiciones reales.
